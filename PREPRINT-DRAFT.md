## Nearest-value matching against anonymised estimates is not validation

### Summary

Audits of published research increasingly compare recomputed values against reported values. When
reported values are anonymised, the natural shortcut is to match each reported value to the nearest
recomputed value within a tolerance and report the match rate. We show that this procedure has no
discriminating power in a realistic setting: with 137 reported values and 437 recomputed values over
a bounded range, a nearest neighbour within 0.01 exists almost always by chance. We also show that
requiring joint agreement on two parameters, with a uniqueness margin, remains inside the null
distribution in our data.

### The test

Data: pooled sensitivity and specificity for diagnostic meta-analyses released as part of a
published systematic review of data-extraction errors, together with the reported pooled values in
its supplement. Reported values are anonymised ("Meta ID 1…N") with no mapping to review, outcome,
or dataset version.

| Method | Observed | Null mean | Null max |
|---|---|---|---|
| Nearest match, sensitivity only (tol 0.01) | 0.993 | 1.000 | 1.000 |
| Nearest match, specificity only (tol 0.01) | 1.000 | 1.000 | 1.000 |
| Joint (sens, spec), unique assignment | 50/137 | 40.9/137 | 53/137 |

The null distribution was generated by replacing each reported value with a random draw from the
recomputed distribution (500 replicates for single-parameter, 200 for joint).

### Implication

A match rate of this kind cannot distinguish a correct implementation from an arbitrary one. Where
anonymisation prevents verified mapping, the honest report is that validation is **blocked** — not
that agreement was achieved. We recommend that any reported reproduction statistic be accompanied
by a null distribution generated the same way; a statistic without one is unfalsifiable.

### A second bound: most rows contain nothing to verify

In a manual inspection of seven tables across two open-access diagnostic meta-analyses (43 and 40
included studies), no table contained per-trial contingency cells; all reported per-study
percentages with sample sizes. Across a wider automated pass, 242 of 253 table rows (96%) contained
no cells.

If this generalises — and our sample is too small to establish that it does — the dominant error
class in evidence synthesis cannot be detected from the review alone, because a transcription error
in a percentage is invisible without the primary document.

### Limitations

- Two data sources; one field; small manual sample.
- The null test is specific to the density of these value sets; other densities will give other
  null rates. The method, not the number, is the point.
- We make no claim about the frequency of errors in any review or field.
